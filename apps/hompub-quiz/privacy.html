Privacy Policy

Effective: Pilot — November 2026 (quiz library, Focus check, question pictures and typed answers added) Applies to HomPub Quiz, pilot quiz web app
The short version

HomPub Quiz holds a nickname, answer choices and a score for each student for the length of one lesson, on one small server we call the referee, and then deletes them. There are no student accounts, no cookies on students' phones, no analytics and no ads. The teacher signs in with one host passcode, which sets a single sign-in cookie in the teacher's own browser. The teacher's quizzes, and any pictures the teacher adds to questions, are kept in the teacher's quiz library on the server until the teacher deletes them; the library holds no student data. If the teacher turns on Focus check, the referee also notes when a student left the quiz page during a question, and students are told so on screen. HomPub itself sees nothing. The only lasting copy of a game is the results file the teacher downloads.

Everything below is the detail behind those sentences.

Information we collect

From students: a nickname (typed, or, if the teacher allows it, picked from a list of random two-word names — no real name is required or wanted), the answer chosen for each question (for a question with a typed answer, the text the student typed, up to 80 characters), and the time each answer arrived at the referee. A student may change the nickname up to three times while the teacher allows it, and the teacher can correct any nickname.

From students, only when the teacher turns on Focus check: for each question, how many times the student's phone left the quiz page (switched app or tab, minimised, or locked the screen) while the question was open, for how many seconds in all, and how many attempts to copy the question were blocked. Nothing else about the phone is read: no other apps, no screen contents, no location. Whenever Focus check is on, every student's screen says "Your teacher can see if you leave this page during a question." It is a signal for the teacher, not proof, and it never changes a score.

From the teacher: the host passcode, checked at sign-in and never stored as typed; the teacher's quizzes — titles, questions, options, the correct answers, explanations, and pictures with their descriptions — kept in the teacher's quiz library; and a random host token so a game can be resumed if the laptop drops off the network. A picture is made smaller on the teacher's own computer before it is sent. Teachers should not put photos of students, or anything else personal, in quiz pictures.

That is the full list. There are no student accounts and no email addresses. The only cookie is the teacher's sign-in cookie, in the teacher's browser: it says "signed in with the host passcode" and nothing else, lasts 30 days while used (at most 90), or, when the teacher ticks "This is a shared computer", only until the browser closes, after 4 hours without use, or after 12 hours at most; it is removed by "Sign out on this device", which also clears the game from that screen. Students' phones get no cookies. The pages set no advertising ID and include no analytics or crash reporting. The student page loads no third-party scripts and fetches no fonts from third parties: a classroom of phones talks to exactly one server, the referee. (The one font it can load, Noto Devanagari for Hindi and Sanskrit text, comes from the referee itself, and only when a page shows Devanagari.)

Where it lives, and for how long

A game lives in one Cloudflare Durable Object — a small, single-purpose storage unit — in the Cloudflare data center nearest the teacher who created it. It holds the quiz (including the answer key), the game's settings and current phase, one row per player: nickname, score, streak and the answers given, and, when Focus check is on, the Focus check notes described above. No IP addresses, no device details, no browser details.

The teacher's quiz library lives in one Cloudflare D1 database: for each quiz its content, a version number, a fingerprint of the content, and when it was last changed and deleted. It holds nothing about students or games. A quiz stays until the teacher deletes it; a deleted quiz sits in the library's Trash for 30 days, where the teacher can restore it or delete it for good. Cloudflare keeps a 7-day recovery history of the database (so a mistake or a fault can be undone), so a deleted quiz can remain in that history for up to 7 more days.

Question pictures live in private Cloudflare R2 storage in the same account, named by a fingerprint of the file, together with a record of which quizzes use each one. A picture is deleted 8 days after no quiz (including quizzes in the Trash) uses it any more; the extra day beyond the 7-day recovery history means a recovered quiz never lacks its picture. A picture can be opened by anyone who has its exact link, which a phone receives only when the question is shown; nothing is recorded about who opened it.

A few more things exist outside the game, all to stop misuse:

  • The referee counts how many games are created each day, in total, so nobody can create thousands of games in a day. Creating a game needs the host passcode, so this count is no longer kept per network: it holds no IP address or hash of one, and it is deleted within 48 hours.
  • After five wrong host passcodes from one network in 15 minutes, sign-in from that network pauses for 15 minutes. From the fourth wrong passcode, the referee keeps one keyed one-way hash of the network address with the count, or with the time the pause ends; it is deleted when those 15 minutes are over.
  • To stop people guessing game PINs, the referee counts wrong PINs per network for 10 minutes. These counts live only in the referee's memory, are never written down, and disappear when it restarts.
  • The list of game PINs also records which host passcode started each game, so the teacher can resume it from another signed-in device. It is deleted with the PIN.

It is deleted:

  • when the teacher confirms the results download at the end of the game, or
  • automatically after 2 hours without any activity, or 30 minutes after the teacher presses End game if the download is never confirmed. Once a question has been played, the teacher's screen is warned 15 minutes before such an automatic deletion (with a button to keep the game 2 more hours), and the results file is sent to the teacher's screen just before it.

The only lasting copy of a game is the CSV the teacher downloads: rank, nickname, score and the answer to each question (including any typed answers), and, when Focus check was on, how often and for how long each student left the page. A student the teacher removed from the game is listed too, marked "removed", with the answers given before the removal. What the teacher does with that file is the teacher's responsibility, as with any class record.

On each student's phone, a random reconnect token sits in the browser's storage so a dropped connection can rejoin without losing the score. It identifies the phone to the referee for that one game only, and it is cleared when the game ends. Each browser tab also keeps a random tab id in its own session storage, so the referee can tell a second tab from the same tab reconnecting; it is forgotten when the tab is closed. When Focus check is on, a phone that could not report straight away keeps its counts for the current and previous question in that tab's session storage until it can. The teacher's browser keeps a copy of the teacher's quiz library, so quizzes can be edited without a connection, plus the PIN and host token of the current game. "Export" files made by the teacher contain the quizzes and their pictures. "Sign out on this device" removes the quiz copy from that browser, unless a change in it could not be saved to the library yet.

What HomPub sees

Nothing about any game. Request logging is switched off on the referee. No IP addresses, nicknames, quiz contents or scores are logged or forwarded to us. The only figures we see are the hosting provider's aggregate request counts, which say nothing about who played or what was asked.

Third-party services

Cloudflare hosts the referee. To route traffic it processes connection metadata — IP address and timing — under Cloudflare's own privacy policy, just as GitHub does for this website. HomPub does not receive that metadata.

No advertising network, no analytics SDK, no crash reporting service and no social-media widgets are included on any page.

Children's privacy

HomPub Quiz is built for classrooms, so most players are children, and the design starts from that. A student is known to the referee only by a nickname, which is never linked to an account, email address, device identifier or any other persistent identifier. Nothing about students is retained once the lesson ends, including anything a student typed as an answer, and the quiz library never holds student data. Typed answers are never shown on the projector, only in the teacher's results file. Focus check is off unless the teacher turns it on, students are always told when it is on, and its notes are deleted with the game. The teacher is the only person who ever holds a copy of the results.

Schools that want even the nickname-and-score data to stay entirely under their own control can deploy their own copy of the referee, because it is open source.

Fairness and timing

Answers are timed on the referee's clock, not the phone's, so nobody gains by changing their device's time. The flip side: a student on a slow connection may lose a few points per question in speed mode, because their answer takes longer to arrive. Teachers who want to remove that effect can run the game in accuracy mode, where every correct answer is worth the same.

Changes to this policy

This is a pilot, and the service will change. If it changes in a way that affects this policy — for instance, if a future version stores anything beyond what is listed here — this page will be updated first, and the "Effective" chip above will change accordingly.
